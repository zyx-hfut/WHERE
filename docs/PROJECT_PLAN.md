# WHERE 项目计划

## 1. 需求分析与边界

WHERE 的核心不是“云端账号系统”，而是一个 local-first 的个人物品位置账本：用户在没有网络和没有 LLM 的情况下，也必须能够快速新增、查看、修改和追溯物品位置。

需求分为四条主线：

| 主线 | 首要目标 | 后置能力 |
| --- | --- | --- |
| 物品记录 | 列表、物品、位置、备注、图片/图标、历史 | 批量操作、快捷键、导入导出 |
| 本地账号 | 本地注册、切换账号、密码保护、独立数据 | 恢复密钥、加密备份 |
| 智能体 | 查询和修改均通过受控工具执行，显示工作流 | 多 Provider、流式输出、丰富 RAG |
| 双端同步 | 加密导出/导入、冲突预览和人工选择 | 局域网/中继服务、增量同步、实时推送 |

### 首版明确不做

- 不在 V0/V1 引入必须联网的中心化账号服务。
- 不让 LLM 直接执行任意 SQL 或直接修改数据库。
- 不把向量数据库作为首个 RAG 依赖；功能文档规模小，先用 SQLite FTS5/BM25。
- 不在同步前承诺“自动无冲突”；所有无法证明安全合并的变化都进入冲突队列。

## 2. 推荐技术路线

### 应用层

- React + TypeScript + Vite：构建 SPA，PC 与移动端复用同一套界面和领域类型。
- Tauri 2：使用系统 WebView，Rust 承担文件、数据库、密钥和同步等本地能力。
- SQLite：单机事务数据库；启用 WAL，避免把数据库复制过程误当作同步协议。
- Rust 数据访问：优先使用 `rusqlite` + 显式 migration；如果异步任务明显增多，再评估 SQLx。

### 智能体层

- Provider Adapter：统一 `baseUrl / apiKey / model / headers / capabilities`，支持 OpenAI-compatible 接口。
- Tool Registry：工具有稳定名称、版本、输入/输出 schema、权限等级和是否需要确认等元数据。
- Agent Orchestrator：负责意图识别、RAG、工具选择、执行、结果总结和步骤事件流。
- RAG：功能文档以 Markdown/JSON 管理，构建时或首次启动时切分并写入 FTS5；后续可增加 embedding，但不改变工具接口。

## 3. 领域模型

核心实体如下：

```text
Account
  └─ ItemList
       └─ Item
            ├─ Note
            ├─ Attachment/Icon
            └─ ItemHistory[]

Account
  ├─ Conversation ─ Message[] ─ AgentRun ─ AgentStep[]
  ├─ LlmPreset
  └─ SyncDevice / SyncChange
```

### 关键设计决定

1. 物品使用稳定 UUID，不使用“名称”作为主键；名称、列表、位置均为可编辑字段。
2. “放在”“存有”是初始化时创建的普通列表，之后允许重命名或删除；删除列表前必须处理其中物品。
3. 每次创建、修改、删除物品或备注都在同一事务中写入 `item_history`。
4. 历史记录保存操作类型、发生时间、操作者设备、变更前后快照，便于审计和同步。
5. API Key 使用操作系统安全存储；SQLite 只保存预设元数据和安全存储引用。密码使用 Argon2id 哈希，绝不保存明文。
6. “找回密码”在纯本地模式下实现为恢复密钥/恢复文件流程，而不是伪装成邮箱找回。

## 4. 分阶段路线图

### V0.1.0-planning：项目基线（当前）

- 完成需求拆解、架构约束、数据模型和版本计划。
- 建立 README、CHANGELOG 和文档目录。
- 建立 Git 基线和后续提交规范。

验收：新开发者能从 README 知道当前状态、技术路线、开发前置条件和下一步。

### V0.2.0-shell：可运行应用壳

- 初始化 Tauri 2 + React + TypeScript + Vite。
- 建立三栏/三页面导航：物品、智能体、我的。
- 建立 Rust command 边界、前端 domain 类型、统一错误格式和基础主题变量。
- 接入空数据库初始化与 migration runner。

验收：PC 可启动；页面切换流畅；数据库能创建并完成 migration；单元测试和构建通过。

### V0.3.0-items：本地物品位置闭环

- 默认列表“放在”“存有”。
- 列表切换、新增/编辑/删除物品、备注、默认图标。
- PC 右键菜单、双击位置编辑；移动端手势入口预留。
- 空状态、加载状态、错误反馈和键盘快捷键。
- 所有写入事务化并生成历史。

验收：离线完成基本 CRUD；重启后数据不丢失；历史记录与实际变更一致；常用操作无需等待网络。

### V0.4.0-history-media：历史与媒体

- 历史查看、按物品过滤、时间格式化。
- 图片选择、替换、删除；图片存文件系统，数据库仅保存受控引用和元数据。
- 数据库备份/恢复前置能力和迁移测试。

验收：图片不阻塞列表首屏；历史可追溯；数据库升级有回滚/备份策略。

### V0.5.0-account：本地账号

- 本地注册、登录、锁定、切换账号。
- 账号独立数据目录/数据库命名空间。
- Argon2id 密码哈希、恢复密钥、导出加密备份。
- 设置页中的安全提示和数据目录说明。

验收：不同账号数据完全隔离；错误密码不能读取业务数据；恢复流程经过测试。

### V0.6.0-agent-read：只读智能体

- LLM Provider/模型预设的保存、加载和测试连接。
- 功能文档 RAG：搜索当前能力说明并引用到智能体上下文。
- 查询工具：按名称、位置模糊检索；类别/电子设备等模糊查询先由 LLM 提出候选，再由本地检索验证。
- 对话新建、继续、消息历史。
- AgentRun/AgentStep 事件流可视化，显示每一步名称、状态和摘要。

验收：没有写权限的智能体无法修改数据；无 LLM 时基本页面仍可用；查询结果能追溯到实际本地数据。

### V0.7.0-agent-write：受控写操作

- 新增、修改、删除列表/物品、备注和图片的工具。
- 修改/删除默认展示变更预览并由用户确认；低风险查询可直接执行。
- 幂等 key、工具超时、错误重试和取消运行。
- Agent 工作流中展示“理解请求—检索—确认—执行—总结”。

验收：案例 1~5 可测试复现；LLM 输出不符合 schema 时不会写库；每次智能体写操作都有历史记录。

### V0.8.0-sync-file：安全文件同步

- 设计设备身份、数据库/变更包版本和同步协议。
- 加密导出/导入，支持 PC 与手机通过文件、二维码或用户选择的传输方式交换。
- 同名不同位置、同一 UUID 两端均修改等冲突进入可读冲突列表。
- 提供“采用 PC、采用手机、保留二者/另存为”三类人工决策。

验收：同步失败不破坏原数据；冲突不会静默覆盖；导入前可预览，导入后可撤销/恢复备份。

### V0.9.0-polish：体验与发布准备

- 夜间模式、主题切换、使用说明、无障碍和响应式细节。
- 性能预算、崩溃日志的本地脱敏导出、数据库完整性检查。
- Windows/Android 构建流水线、版本号、变更日志和发布包校验。

### V1.0.0：稳定版

- 完成三端核心体验、同步协议稳定化、迁移兼容策略和用户文档。
- 评估可选的自托管同步中继服务；它不能成为离线基本功能的前置条件。

## 5. 同步方案原则

同步不直接复制正在使用的 SQLite 文件，尤其不能只复制 `.db` 而忽略 WAL 文件。推荐将同步对象设计为版本化、加密的变更包：

```text
本地事务
  -> SyncChange (device_id, sequence, entity_id, base_version, payload)
  -> 加密导出/传输
  -> 对端校验签名/版本
  -> 自动合并或生成 Conflict
  -> 用户选择后事务性应用
```

第一版采用“完整加密快照 + 变更元数据”也可以，先保证可靠性；当数据量和同步频率验证后，再升级为增量变更同步。同步冲突的判断必须基于稳定 ID、版本和时间/设备信息，而不是仅比较显示名称。

## 6. 质量门禁

每个版本合并前至少通过：

- TypeScript 类型检查、Lint、单元测试、Rust 测试。
- 数据库 migration 从空库升级和从上一版本升级测试。
- 关键用户流程的 Playwright 冒烟测试。
- 智能体工具 schema、权限、幂等和错误路径测试。
- 同步冲突的三种人工决策测试。
- Git 提交信息符合 Conventional Commits，并在 CHANGELOG 中记录。

## 7. 待确认产品决策

这些问题不会阻塞 V0.2~V0.4，但在对应版本前必须明确：

- 同一账号是否允许多个同名物品；若允许，列表项需要可选别名/图片区分。
- 手机首发平台是 Android 还是同时支持 iOS；iOS 构建必须在 macOS 上完成。
- 同步默认方式是文件/二维码、局域网直连，还是自托管中继。
- 是否允许把 LLM 请求内容发送给第三方 Provider；需要隐私提示、脱敏和关闭联网选项。
- 删除列表和物品是软删除、回收站，还是立即删除后仅依赖历史恢复。
