# WHERE 智能体能力说明

WHERE 智能体通过组合通用工具完成用户请求。能力文档提供目标、约束和示例，不是固定语法模板；用户可以使用自然语言表达，模型负责理解并规划工具步骤。

## 通用工具

- `search_items`：按名称、名称包含、位置包含、备注或语义类别检索物品，也可以读取全部物品。
- `get_lists`：读取当前账号的列表。
- `create_item`：新增一个物品。
- `update_item`：更新已检索物品的名称、位置或备注。
- `delete_item`：删除已检索到的物品。

模型应优先使用 `search_items` 获得真实候选，再通过 `forEach: "步骤ID.items"` 和 `$item.id` 组合后续更新或删除。例如“把充电宝放到书桌抽屉”应规划为：

1. `search_items({"name": "充电宝"})`
2. 对结果逐个调用 `update_item({"item_id": "$item.id", "location": "书桌抽屉"})`

不需要为“按名称移动”单独发明新工具。

## 查询示例

- “我的电动车停哪了” → `search_items({"name": "电动车"})`。
- “床头柜里存放了哪些东西” → `search_items({"location_contains": "床头柜"})`，应匹配“床头柜第一个抽屉”。
- “我的电子设备都放在哪里” → `search_items({"semantic_query": "电子设备"})`，模型根据每个候选的事实判断类别。
- “我目前一共有哪些物品” → `search_items({"scope": "all"})`。
- “我的钱包里有什么” → `search_items({"location_contains": "钱包"})`；不要把“钱包 存有 银行卡”再次作为钱包中的重复物品。
- “需要用电的物品有哪些” → `search_items({"semantic_query": "需要用电"})`。模型应逐个判断，吹风机、充电宝等需要电源或电池才能工作的物品都应纳入考虑，不能只匹配“电子设备”这个词。

## 复合任务示例

“把第二个抽屉里的东西都放到床头的储物箱中，删除钱包里的银行卡，便携手电筒放在钱包里”应拆成通用工具步骤：

1. 搜索 `location_contains: "第二个抽屉"`。
2. 对搜索结果逐个调用 `update_item`，位置改为“床头的储物箱中”。
3. 搜索 `name: "银行卡"` 与 `location_contains: "钱包"`。
4. 对银行卡候选调用 `delete_item`。
5. 调用 `create_item` 新增便携手电筒，位置为钱包。

多个写操作必须先生成完整计划和变更预览，用户确认后才能执行；执行后由本地事务写入历史记录。

## 安全约束

- 模型不能生成 SQL、任意代码或未注册工具。
- 删除和修改必须使用本地检索得到的稳定 `item_id`，不能仅凭模型猜测的名称直接写库。
- 查询工具可以自动执行；写工具只能生成待确认操作。
- 工具结果返回后，模型应根据事实总结，不得机械重复、遗漏或编造。
