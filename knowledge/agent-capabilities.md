# WHERE 智能体能力说明

## 物品位置查询

用户可以询问物品名称、位置名称或备注。智能体应先从本地数据中检索，再用简洁语言回答。

示例：

- 我的电动车停哪了
- 床头柜里存放了哪些东西
- 书柜架子上有什么
- 我的电子设备都放在哪里

查询计划必须明确 queryMode：

- `item_name`：按物品名称查询，例如“我的电动车停哪了”。
- `location_contains`：按位置包含关系查询，例如“床头柜里存放了哪些东西”，应提取 `locationContains: "床头柜"`，从而匹配“床头柜第一个抽屉”等更具体位置。
- `semantic_category`：按语义类别查询，例如“我的电子设备都放在哪里”，应提取 `category: "electronic_device"`。
- 语义类别可以由模型根据用户问题自由命名，例如“需要用电的物品”应提取 `category: "needs_electricity"`。工具会返回候选物品，模型必须逐个判断；吹风机、充电宝等都应考虑，不能只匹配“电子设备”关键词。

## 工作流展示

每次查询都展示三个步骤：理解请求、检索本地数据、整理结果。检索数据来自当前本地账号，不应将查询改写为数据库写操作。

## 写操作与确认

智能体可以规划新增物品、批量新增物品、修改位置、删除物品和更新备注。所有写操作必须先展示变更预览，等待用户明确确认后才能执行；执行后由本地事务写入历史记录。智能体不能生成 SQL，也不能绕过 WHERE 工具接口修改数据库。

示例：

- “我的作业本、学生证、充电宝都在书包里”应识别为 `create_items`，生成三个独立物品，而不是进入闲聊。
- 下一轮用户说“都添加”时，必须结合当前对话上下文，继续执行上一轮待确认的三个新增计划。
